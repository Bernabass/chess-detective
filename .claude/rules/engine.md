# Engine and generator rules

- Board: 0x88 layout in an `Int8Array(128)`. `square = rank * 16 + file`, off-board test `sq & 0x88`. Pieces: `0` empty, `1..6` = white P N B R Q K, negatives for black.
- Moves are encoded as numbers in hot paths (from, to, promotion, flags packed into bits). Convert to UCI/SAN only at the edges.
- `make`/`unmake` with an undo stack; no position cloning inside search loops.
- Zobrist keys are two 32-bit halves (no BigInt in hot paths), generated from a fixed seed so keys are identical across runs and machines.
- Public API is exported only from `packages/engine/src/index.ts`. Everything else is internal.
- Every analyzer rule has a stable `RuleId`, a unit test that triggers it, and a test showing it does not fire on legal positions.
- A rule may report `severity: "illegal"` only when the contradiction is mathematically certain. Anything weaker is a `deduction` or is not reported.
- Retractions are generated by geometry, then each one is confirmed by forward move generation from the prior position (soundness by construction).
- Property tests use `fast-check` with a fixed seed printed on failure. Positions come from seeded random legal play from the start position, not only from hand-written FENs.
- Slow tests (perft depth 5+, long property runs, brute-force cross-checks above 4 plies) live in `*.slow.test.ts` and run only with `test:slow`.
- The proof-game lower bound must stay **admissible** (never overestimates). Watch the castling trap described in SPEC §6.3. Any change keeps the admissibility property test green.
- The solver accepts `timeLimitMs`, `nodeLimit` and a `shouldStop()` callback, and reports `status: "complete" | "limit" | "aborted"`. A search that hit a limit must never be reported as "no solution".
- The generator uses node limits only, never time limits, so a candidate's verdict (and the generator's output) is deterministic whatever the machine, its load or `--jobs`.
- Generator output is byte-identical for a given `--seed`, options and engine version, whatever `--jobs` is.
- `fixtures/*.json` are generated by `pnpm --filter @retrograde/engine fixtures`. Never hand-edit generated fixtures; regenerate them and commit the result.
